## 当前已确认的遗漏

此前项目整理时，对本次项目已经沉淀在 Git 中的目录结构及其归属说明记录不完整。本文件作为 V1.0 知识库补充，明确记录：

1. 项目目录本身属于项目资产的一部分，应作为 AI 后续理解项目上下文的依据。
2. Product、Design、Engineering、前端代码、知识库/AI 内容需要保持清晰的职责边界。
3. 当前预览页如果展示后台管理界面，不代表整个项目的前台业务被替换为后台；前台与后台应分别作为不同产品界面进行管理。
4. 项目目录导航页面位于 `docs/project-directory.html`，用于从浏览器可视化访问 Git 中的主要项目目录。

本次项目的核心业务模型为：

**城市 → 医院 → 院区 → 科室 → 医生 → 日期/号源 → 挂号**

当前阶段属于能力建设阶段，暂不指定具体提升指标；单院区医院可跳过院区选择。

## 后续维护原则

新增 Product、Design、知识库、开发及测试资产时，应优先归入已有职责目录，避免在根目录重复创建同类内容。若目录职责发生调整，应同步更新本知识库说明。
