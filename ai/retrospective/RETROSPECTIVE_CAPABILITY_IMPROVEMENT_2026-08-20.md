# Retrospective — Stage Capability Improvement 2026-08-20

## Why We Added This Document
本轮流程已经形成 Agent、Project Data Asset、Knowledge Base、Retrospective 等体系，但缺少独立层回答“每次优化到底带来了什么能力提升”。因此新增 Stage Capability Improvement，作为能力演进基线，而不是新增 Agent。

## What Was Added
1. Traditional vs AI Native 流程对比。
2. Efficiency / Quality 双维度衡量。
3. L0–L4 自动化等级。
4. Target 与 Actual 分离。
5. Project Initiation Capability Baseline。
6. One Input, Multi-use 原则。
7. 每轮优化的 Improvement Record。

## Why We Chose L4 for Project Initiation
立项阶段由 Agent 自动收集信息、检查完整度、最小化追问并生成 Draft Plan，但 Plan Baseline 仍需要用户确认，因此属于 Autonomous with Human Gate，而不是完全无人参与。

## Expected Value
目标是减少低价值的录入、整理、重复确认、计划编排和报告准备工作，同时提升信息完整性、数据可追溯性和计划可解释性。设计阶段的 60%–80% 等效率区间仅作为目标，不作为已验证收益。

## Measurement Principle
上线前记录 Target；上线后从实际 Project Execution Record、Stage Output、Model Usage 和 Interaction Data 计算 Actual。效率提升必须与质量指标同时验证，避免单纯追求自动化导致质量下降。

## Final Value
项目以后不仅能记录“做了什么”，还可以持续回答“为什么优化、优化后能力提升了什么、是否真的提升、质量是否同步提升、下一轮优化什么”。
