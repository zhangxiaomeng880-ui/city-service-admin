# V1.0 Frontend Acceptance Scope

## Purpose
The current stage validates the end-to-end product workflow from Product → Design → Frontend Coding → Preview → Acceptance.

## In Scope
- Functional acceptance: city selection, department selection, doctor listing, doctor search, add/edit entry behavior.
- Interaction acceptance: active states, selectors, search, modal, empty states and feedback.
- Visual acceptance: hierarchy, typography, spacing, colors, controls and table density.
- Responsive acceptance: supported desktop viewport widths and layout stability.
- Mock-data acceptance: frontend state and data transitions using local mock data.

## Out of Scope
- Backend/API integration.
- Real hospital/doctor data synchronization.
- Authentication/permissions.
- Performance/load testing.
- Production data correctness.

## Stage Gate
The current stage passes when the core frontend workflow can be demonstrated end-to-end with mock data and no blocking functional/visual/adaptation defect is found.

Quality review and backend integration are subsequent stages.
