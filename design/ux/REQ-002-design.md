# REQ-002 Design：科室挂号领域迁移

## 1. Design Goal

在不改变现有信息架构和核心交互的前提下，将产品视觉与交互语义从“城市服务”迁移为“科室挂号”。

本阶段属于领域迁移 Design，不是重新做一套 Figma 高保真设计。

## 2. 页面结构

### 后台

```text
科室挂号后台
│
├── 城市下拉
│
├── 左侧：科室列表
│    ├── 科室名称
│    ├── 编辑
│    └── 删除
│
└── 右侧：医生列表
     ├── 医生名称
     ├── 所属科室
     ├── 编辑
     └── 排序
```

### 前台

```text
科室挂号
│
├── 城市切换
│
├── 科室
│
└── 医生列表
```

## 3. 核心命名规范

| 现有 | 迁移后 |
|---|---|
| 城市服务 | 科室挂号 |
| 一级分类 | 科室 |
| 二级服务 | 医生 |
| 服务列表 | 医生列表 |
| 服务管理 | 医生管理 |
| 分类 | 科室 |

## 4. 交互迁移

### 城市

- 城市继续位于分类导航上方。
- 城市通过下拉列表切换。
- 切换城市后，左侧展示该城市关联的科室。
- 选择科室后，右侧展示该科室下的医生。

### 科室

- 支持编辑。
- 支持删除。
- 存在医生时禁止删除。
- 无医生时允许删除。
- 保留当前已有的排序能力。

### 医生

- 第一阶段仅作为现有二级服务的领域语义迁移。
- 不新增医生详情、医院、职称、头像等字段。
- 列表继续沿用现有二级层级列表的交互结构。

## 5. 状态设计

### 无科室

左侧显示空状态；右侧不展示无归属医生。

### 科室无医生

右侧展示空状态，并允许继续管理科室。

### 删除科室但存在医生

禁止删除，并提示：

> 该科室下已有医生，无法删除。

### 删除科室成功

刷新左侧科室列表，并清理当前无效选中状态；右侧不保留已删除科室的数据。

### 城市切换

切换城市后重新加载该城市对应的科室与医生数据，不能继续展示上一城市的数据。

## 6. 视觉迁移原则

- 保持当前页面布局和视觉体系，不因为领域迁移重新设计整个页面。
- 保持左侧科室导航、右侧医生列表的主要视觉层级。
- 文案替换后重新检查长度、换行、对齐和列表密度。
- “医生列表”中需要展示所属科室时，保持信息层级清晰。
- 不因为新增“医生”语义而擅自增加头像、医疗图标或卡片结构。

## 7. Figma 设计边界

当前阶段已经可以输出：

- 页面信息架构
- 页面模块关系
- 交互状态
- 文案规范
- 组件层级要求
- 视觉迁移原则

当前阶段**不能等同于完整 Figma 高保真设计交付**。完整 Figma 细节设计通常还需要实际页面代码/现有视觉稿作为基准，并进一步确定：

- 精确尺寸
- 间距
- 字号
- 字重
- 颜色
- 圆角
- 阴影
- 图标
- 响应式规则
- 全量状态稿
- 组件 Variant
- Design Token

因此本次 Design 先作为 Engineering 的设计约束，而不是虚构一套不存在的 Figma 稿。

## 8. Design 验收标准

- [ ] 后台页面能够明确表达“科室挂号”
- [ ] 左侧明确为科室导航
- [ ] 右侧明确为医生列表
- [ ] 城市位于科室导航上方并可切换
- [ ] 医生列表可表达所属科室
- [ ] 科室删除规则在交互上明确
- [ ] 城市切换后的数据状态明确
- [ ] 不引入本需求范围之外的医疗业务视觉元素
- [ ] 不改变现有核心布局
