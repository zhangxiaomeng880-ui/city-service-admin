# REQ-001：一级分类支持编辑和删除

## User Story

作为城市服务后台运营人员，我希望能够编辑和删除当前城市下的一级分类，以便维护城市服务分类结构。

## 目标

完善一级分类管理能力，同时保证一级分类与二级服务之间的数据关系完整、安全。

## 功能范围

### 编辑

- 支持进入一级分类编辑操作
- 可修改一级分类名称
- 编辑后保存，左侧分类列表更新
- 编辑不改变该分类下二级服务的归属

### 删除

- 一级分类无二级服务时允许删除
- 一级分类存在二级服务时禁止删除
- 删除前需要用户确认
- 删除成功后左侧分类列表刷新
- 删除后不能产生无归属的二级服务

## 非目标

本需求暂不包含：

- 城市新增、编辑、删除
- 二级服务批量迁移分类
- 删除分类时级联删除二级服务
- 分类跨城市迁移

## 核心业务规则

| 场景 | 操作 | 结果 |
|---|---|---|
| 分类无二级服务 | 删除 | 允许删除 |
| 分类有二级服务 | 删除 | 禁止删除，并提示先处理关联服务 |
| 分类编辑 | 修改名称 | 允许保存 |
| 分类编辑 | 修改后取消 | 不产生变更 |

## 验收标准

- [ ] 一级分类列表存在编辑入口
- [ ] 一级分类列表存在删除入口
- [ ] 编辑可修改分类名称并正确保存
- [ ] 编辑取消不会产生数据变更
- [ ] 无二级服务的分类可以删除
- [ ] 删除前有确认步骤
- [ ] 有二级服务的分类不能删除
- [ ] 禁止删除时明确提示原因
- [ ] 删除成功后左侧分类列表正确刷新
- [ ] 删除不会产生无归属二级服务
- [ ] 前台发布数据不会出现孤儿服务

## 依赖与风险

- 需要确认当前分类实体与城市关联的实际数据结构
- 需要确认前台读取的是实时数据还是发布数据
- 如果当前分类删除逻辑尚不存在，需要同步补充后端校验，不能只依赖前端按钮禁用
